## 문의 배경

KPubData는 공공데이터포털(data.go.kr)의 Open API를 이용하는 오픈소스 Python 라이브러리입니다.
사용자가 자신의 API 키를 이용해 데이터를 조회하고, 이를 정제·분석·게시하는 도구를 제공합니다.

게시된 이용약관 및 활용가이드에서 확인할 수 없는 세 가지 사항을 문의드립니다.

---

## 질문 1: 호스팅 BYOK 서버 경유 호출

**질문:** 사용자가 자신의 API 키를 입력하면, 사용자를 대신하여 우리가 운영하는 서버에서
해당 키로 API를 호출하는 서비스(Bring-Your-Own-Key 방식)를 운영하는 것이 허용됩니까?

**구체적 시나리오:**
1. 사용자가 웹 UI에서 자신의 data.go.kr API 키를 입력
2. 우리 서버가 해당 키로 `apis.data.go.kr` 호출
3. 결과를 정제하여 사용자에게 표시 (데이터는 저장하지 않음)

**확인 필요 사항:** 이용약관 제5조(이용자의 의무)에 "계정 공유 금지" 조항이 있는지,
BYOK 방식이 이에 해당하는지 여부.

---

## 질문 2: 비한국 IP에서의 접근

**질문:** 한국 외 IP 주소에서 data.go.kr Open API를 호출하는 것의 공식 정책은 무엇입니까?

**배경:** 일부 API에서 결과코드 32(`UNREGISTERED_IP`)가 반환되는 것을 확인했습니다.
이것이 다음 중 어느 것인지 명확히 하고 싶습니다:
- (a) 모든 API에 대한 정책적 차단
- (b) 특정 API에만 적용되는 보안 정책
- (c) 키 등록 시 한국 IP를 요구하는 등록 요건

해외 거주 개발자도 KPubData를 사용할 수 있는지 판단하기 위해 답변이 필요합니다.

---

## 질문 3: 파생 데이터셋의 출처 표시 형식

**질문:** 공공누리 라이선스(제1~4유형)가 적용된 데이터를 정제·변형하여 파생 데이터셋을
게시할 때, 요구되는 구체적인 출처 표시 형식은 무엇입니까?

**구체적 확인 사항:**
- 필수 포함 항목 (예: 기관명, 데이터명, 라이선스 유형, 원본 URL)
- 표시 위치 (데이터셋 설명란? README? 각 파일? 메타데이터?)
- 표시 형식 예시 (문구 템플릿이 있는지)

**배경:** 현재 게시된 20개 파생 데이터셋 중 17개가 출처 표시 없이 게시되어 있어
이용조건 위반 소지가 있습니다 (builder#677). 준수하기 위해 정확한 형식이 필요합니다.
